# 26.3 走马灯验证构建

本轮版本为 `3.13.0.9-marquee.1`，用于验证小字号文字低速滚动时的字间距抖动。
保留现有 MiSans 定制，只构建 Fabric、NeoForge 两个包；暂不回迁其他 Minecraft 版本。

## 实现

采用固定字形布局、绘制时整体平移的路线。保持按实际字号生成字形，不通过提高最低
滚动速度、放大 HUD 或强制所有文字使用 SDF 来隐藏问题。

- Minecraft GUI：保留绘制矩阵里的浮点平移；逐字取整只作用于固定布局，文字原点和
  阴影偏移在其后应用。字体图集按段选择过滤方式：像素对齐、纹理与屏幕像素一一对应
  时沿用原采样器，分数像素位置或缩放不匹配时对轮廓字体使用线性采样。
- 轮廓字体的四边形包含已有图集中一像素的透明边框，并扩大准备阶段的包围盒。
  这让边缘的插值覆盖率有空间绘制，避免被紧贴字形的几何边界截断。
- MUI Canvas／TextView：通过 Arc3D `GraniteDevice` 的 Mixin，将仿射变换的平移
  从字形烘焙矩阵中移出。文字缓存因此可以跨滚动位置复用，实际绘制仍使用原 Canvas
  变换和文字原点；Arc3D 根据最终小数位置选择线性采样。透视变换继续走已有逻辑。
- 保留原有 SDF 选择、彩色 emoji、位图字体和自定义图标的纹理／采样路径。
  新采样器来自 Minecraft 自身的缓存，使用现有图集，不创建额外帧缓冲或 GPU 纹理。

MC GUI 与 Canvas 是两套实现，采用同一定位原则。修复位于 ModernUI 内，已有
MusicHud 跑马灯调用不需要更换接口。

## 自动检查与人工验证边界

`./gradlew :common:checkTextMarquee` 检查真实 `TextRunRenderState` 输出的连续帧
顶点：不同 GUI 缩放、小字号、正反方向的小步位移、阴影、UV 留白，以及像素相位
与采样选择。还检查 Arc3D 的实际缓存键、子段变换与过滤选择、固定版本的 Mixin
注入点和两个加载器的注册。该任务随 `check` 和 Actions 的 `build` 执行。

这些检查没有启动图形设备，不代表动画观感或 OpenGL／Vulkan 已验收。
GitHub Actions 的 `modernui-mc-release-jars` artifact 提供对应两个加载器的验证包。
分支推送只编译，不创建正式 Release。

## 建议验证场景

1. 使用相同 MusicHud 配置和较长的中英文标题，对比旧版与本构建。把文字缩到问题
   容易出现的大小，分别检查静止、刚开始缓慢移动、正常滚动及循环接缝。
2. 对照 GUI 缩放 1、2、3、4；保持字号与窗口大小一致。观察字符相对间距、细竖线
   的亮度变化、移动时清晰度及停止后的外观，而不只观察文字整体是否移动。
3. 检查阴影、歌词／标题中的图标与 emoji、裁剪边缘、窗口调整及字体重载。
   MUI 页面中也检查滚动文字；重新打开页面并运行一段时间，检查图标是否仍可见。
4. 分别使用实际物理显卡的 OpenGL 与 Vulkan；记录加载器、GPU／驱动、GUI 缩放、
   HUD 字号与复现内容。连续录屏有助于区分字间距抖动、边缘闪烁与掉帧。

线性采样可能带来轻微软化，本轮需要确认其与低速稳定性的实际取舍。用户确认效果后
再决定后续调整和回迁；MiSans 拆分另行处理。
